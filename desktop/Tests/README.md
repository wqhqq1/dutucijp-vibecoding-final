## 实测摘要

2026-10-23（Asia/Shanghai），Windows 10.0.26340 / win-x64，.NET SDK 9.0.316。源时间精度后为31项，账户搜索/角标后为34项；本次再补派单国家覆盖、全选分页计数及排除/缺国家分支，最终 Release 运行退出码0：

```text
RESULT 38/38 passed; 0 failed
```

测试过程中先发现并复现原输入点段路径绕过、导出缺 Origin、导出非 JSON 错误不可读、设置保存失败造成连接状态半提交等问题；产品负责人修复后由这些用例复验通过。也验证了负责人补充的代次屏蔽与 Passkey 跨切换保护。最后追加登录后运行列表读取失败用例时，复现了认证本身更新代次导致 Guard 吞掉当前运行读取错误的问题，修复后第30项通过。第一次基础用例运行还出现一次测试 TCP 监听关闭时的 Socket 对象已释放错误，已为测试服务退出增加取消期间的 ObjectDisposedException 处理；后续运行未再出现。这里只记录实际结果，不把失败历史改记为首次通过。

## 隔离与解释边界

- 测试服务只监听 `127.0.0.1` 的系统分配临时端口，通过 `TcpListener` 自行回复 HTTP，无 URL ACL、固定端口或正式 Go 服务依赖。
- 所有身份、Cookie、挑战、恢复码和运行都是内存合成数据；AppViewModel 显式注入初始 ClientSettings 和内存保存回调，不调用 Load/Save，不读取或覆盖用户现有设置。
- `NativeWebAuthnStub.cs` 是测试替身。默认拒绝调用；只有明确的四项合成流程测试配置受控返回或延迟。没有加载 `webauthn.dll`、调用 Windows Hello 或访问实际认证器。
- begin/finish 是写请求，其进行期间后端切换应被拒绝；相应用例验证写锁，再用 NewScope 模拟失效代次。等待合成设备返回的阶段没有 HTTP 写，因此实际切换后端并验证迟到结果被丢弃。
- 这套测试不证明 WinUI 窗口布局、键鼠操作、实体设备 Passkey、TOTP 真机、真实业务数据、生产 Go 端集成或另一台物理机器运行通过。它验证直接链接的客户端网络与状态实现。
- 静态阅读时，Jobs 轮询使用 Guard 占用 Busy，但 UI.Button 并不依赖全局 Busy 禁用，主窗口导航只检查 ActiveWrites；未发现“只要后台轮询就禁止导航”的代码。未将这项阅读结论冒称图形界面实测。

测试只新增本目录源码及说明；产品修复由主代理实施。`bin/` 和 `obj/` 由仓库忽略。
