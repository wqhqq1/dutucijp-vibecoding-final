# 退货对账与差异处理 API 接入指南

协议版本：1.0.0。适用于共用 Go 后端、现有网页和 Windows 原生客户端。机器可读定义见 [openapi.yaml](openapi.yaml)，同时提供等价的 [openapi.json](openapi.json)。本文中的账户、地址和请求值均为示例，不是可用凭据。

## 服务与入口

客户端只连接已启动服务。默认入口 `http://localhost:8080`，服务默认监听 `127.0.0.1`。管理员需要局域网访问时，以现有实例的数据库、私有认证目录启动同一程序，例如：

```powershell
recon.exe serve --db <实例数据库绝对路径> --secrets <原私有认证目录> --project <软件目录> --port 8080 --listen-host 0.0.0.0
```

`--listen-host` 接受 IPv4/IPv6 接口地址，IPv6 使用 `::` 或指定接口；端口仍受原 1024～65535 约束。监听和许可是两个独立条件：先通过本机入口登录管理员，在“许可入口”增加 `http://192.168.1.20:8080`、`http://[fd00::20]:8080` 或实际域名。HTTPS 可沿用已有反向代理，客户端验证系统信任链和主机名，不忽略证书错误。Windows 防火墙、DNS、TLS 反向代理由部署者配置，客户端不会修改系统设置。

许可值是完整 Origin：协议、主机、有效端口；不含路径、参数、片段、用户名、密码或通配符。主机规范化大小写/IDNA，IP 规范化，省略 HTTP 80/HTTPS 443。输入省略协议的历史管理接口仍按 HTTPS 解释；客户端连接页要求显式协议。固定本机入口保留；当前管理入口不能移除。变更使用 `version` 乐观锁，成功会撤销未完成的认证挑战。

先读取 `GET /api/health`，确认 `application == "returns-recon"`；再读取 `GET /api/auth/client-config` 确认 API 版本。`runtime_id` 是启动器/任务命名空间，`backend_id` 是随数据库持久保存的逻辑服务身份，不能混用。数据库备份恢复保留后端身份；独立空库生成不同身份。不要把公开身份标识当作身份验证秘密。

```json
{
  "api_version": "1.0.0",
  "backend_id": "<公开稳定标识>",
  "native_passkey": {"id":"default","rp_id":"localhost","origin":"http://localhost:8080"},
  "legacy_bindings": []
}
```

## 请求、Cookie 与 CSRF

- 路由统一位于 `/api`。保持现有路径，不额外增加 `/v1` 前缀；所有正常成功响应为 HTTP 200。
- JSON 请求使用 `Content-Type: application/json`，单次 JSON 正文最多 1 MiB，普通绑定接口拒绝未知字段和第二个 JSON 对象。
- 每个非 GET/HEAD/OPTIONS 请求发送 `Origin: <实际连接的许可入口>`。Host 必须属于许可入口，Origin 必须与该 Host 对应的入口精确匹配。
- 后端通过 `Set-Cookie` 发放会话，不在 JSON 返回 bearer token。默认 Cookie 名为 `recon_session`；非 8080 端口为 `recon_session_<port>`。应使用平台 Cookie jar 接收实际名称。Cookie 为 host-only、HttpOnly、SameSite=Strict、最长八小时，HTTPS 下设置 Secure。
- 具有会话的写请求发送 `X-CSRF-Token`，取自 `session.csrf`、`GET /auth/me` 的 `csrf` 或 Passkey begin 的 `csrf`。每次发新会话后更新 CSRF。
- Passkey 匿名选择 Cookie 不代表已登录，也无配置/业务权限；login finish 必须携带 begin 返回的 CSRF。
- 不把 Cookie/CSRF、密码、OTP、恢复码、TOTP 密钥写入日志、URL、源代码或公开截图。切换后端地址时丢弃当前 Cookie jar 和全部业务状态，重新登录。

示例（`$env:API_PASSWORD` 等由调用者在私人环境中提供）：

```powershell
$base = 'http://localhost:8080'
$jar = New-Object Microsoft.PowerShell.Commands.WebRequestSession
$login = Invoke-RestMethod "$base/api/auth/login" -Method Post -WebSession $jar `
  -Headers @{Origin=$base} -ContentType application/json `
  -Body (@{id='finance';password=$env:API_PASSWORD} | ConvertTo-Json)
$csrf = $login.session.csrf
$factor = Invoke-RestMethod "$base/api/auth/totp/login" -Method Post -WebSession $jar `
  -Headers @{Origin=$base;'X-CSRF-Token'=$csrf} -ContentType application/json `
  -Body (@{code=$env:API_OTP} | ConvertTo-Json)
$csrf = $factor.session.csrf
Invoke-RestMethod "$base/api/runs" -WebSession $jar
```

## 认证状态流转

1. `GET /auth/setup/accounts` 列出尚未设置密码的预置/新建账户；`POST /auth/setup/start {id}` 仅取得该账户的受限 `setup` 会话，不能重置已有账户。
2. `POST /auth/setup/password {password}` 设置 16～128 字符强密码，状态由 `new` 转到 `password`。
3. 绑定并验证真实 Passkey，或 `POST /auth/totp/enroll {}` 取得 `secret/uri`，展示二维码并 `POST /auth/totp/confirm {code}` 验证。认证成功返回一次性 `recovery_codes`。
4. 安全保存恢复码后 `POST /auth/setup/complete {saved:true}`，才进入 `state=complete, scope=business`。
5. 后续 Passkey 直接登录，或密码验证获得 `login_factor` 会话，再验证 TOTP。`login_factor` 不开放业务。`GET /auth/me` 可恢复当前进程内状态。
6. `/auth/recover {id,password,code}` 只授予重新绑定因素的受限权限；旧恢复码不能复用。重新绑定、保存新码、完成配置后才可业务访问。
7. 密码/因素变更、恢复码重发等敏感操作需要后端认可的近期完整验证，通常五分钟内；收到拒绝时重新完整登录，不绕过。

认证限流、会话撤销、账户删除和权限版本变化都由服务器执行。客户端隐藏菜单只改善体验，不构成授权。`scope` 的有效值包括 `setup`、`login_factor`、`login_passkey`、`business`；账户恢复还会出现 `recovering` 状态。

## Windows 原生 Passkey 与跨入口共用

浏览器继续调用 `/auth/passkeys/...`，遵循浏览器的 WebAuthn 安全上下文及域名规则。服务器许可不能解除浏览器对 HTTP/IP 的限制。

Windows 客户端调用 `/auth/native-passkeys/...`。实际传输地址与固定认证身份分开，因此同一后端的 localhost、IP 和域名入口能使用同一份原生凭据，不将原始 IP 作为 RP ID。

1. 从 `client-config.native_passkey` 读取默认 `id/rp_id/origin`。默认沿用本机 localhost RP，兼容已有本机网页凭据。旧域名凭据可选 `legacy_bindings` 中服务器返回的绑定，不自行填写任意 RP。
2. `POST /auth/native-passkeys/register/begin {id,binding_id}`（需配置权限），或 `POST /auth/native-passkeys/login/begin {binding_id}`（省略 id 为可发现凭据选择，指定 id 为旧凭据兼容）。
3. 保留 begin 的 Cookie、`csrf`、`challenge_id`、`options.publicKey`；通过 Windows 原生 API 调用注册/签名，必须要求用户验证。`clientDataJSON` 包含类型、服务器 challenge、所选绑定的逻辑 Origin、`crossOrigin:false`。
4. `POST /auth/native-passkeys/{register|login}/finish?challenge_id=<id>&binding_id=<同一绑定>`，正文为标准 PublicKeyCredential JSON；二进制使用无填充 base64url。请求头 Origin 仍为**实际连接地址**，不能用逻辑 Origin 替代。
5. 服务器同时验证实际入口、backend_id、固定绑定、账户版本、签名、UP/UV 和一次性挑战。挑战两分钟有效；同一次挑战不能换入口、换原生/浏览器流程或用于另一个后端。

更换地址后重新取挑战并登录，不能把旧挑战/会话转发过去。旧域名凭据只通过仍获准的兼容绑定使用；移除入口不删除原始凭据，重新批准后继续兼容。恢复/权限/数量等业务规则与网页登录相同。取消系统验证只结束本次认证，不应自动改为弱认证。

## 角色、国家与业务状态

`session` 含角色、显示名、国家范围、国家列表、权限版本和 `can_manage_data_jobs`。财务可查询负责国家并派单；仓库仅访问自己的差异和相关证据；管理员管理全部。全局数据任务限管理员或覆盖全部国家的财务。财务可申请负责范围内仓库账户，管理员审批；新账户必须自行首次配置。

单条工作流：财务派单 → 责任人开始 → 核对候选并确认/补充资料重算 → 填写结论关闭。`version` 取最新差异记录。仅当前责任人在处理中可确认和补充；已关闭只读。未解决差异不能凭文字关闭，应填写待补充资料和下一步。

`POST /cases/{id}/remediations` 支持：

| action | 附加字段 |
|---|---|
| `correct_return` | `changes`：只提交有凭据的修改，数量用正整数字符串 |
| `supplement_sale` | `sale`：单号、身份、国家、数量/单价/时间、`document_ref`、`line_ref` |
| `verify_duplicate` | `row_ids`、`canonical_id`、`disposition=duplicate/independent` |
| `wait_materials` | `missing_materials`、`next_step` |
| `recheck` | 无其他业务字段 |

共同字段为 `version/request_id/action/evidence`。相同实质请求重试沿用同一 request_id；修改内容换新 ID。原始记录、初始配对和历史始终保留。同原因保留轮次，原因改变生成关联新问题且未派单。

## 查询、精度和导出

查询使用显式 `run_id`，分页从 1 开始，默认每页 50，最多 100。筛选包含客户、商品、单号、国家、日期、状态、原因、责任人、待补充；交易额外支持类型和分类。交易排序支持 `source/date/invoice/customer/stock/country`、`asc/desc`，其中 `date` 按响应的 `time` 字段排序，同键顺序由后端稳定确定。日期使用来源日期，无隐含 UTC 转换。

金额和单价是任意精度十进制**字符串**；客户编号、商品和单号也是字符串，保留前导零。不得先转换为 double/float，再转回字符串。交易时间可能含六位小数，无时区；只读时原样保留，未更改时回传原始精度。

CSV 使用 `/exports`，沿用完整筛选和排序，导出所有匹配行，不局限当前页；财务/管理员权限由后端检查。保存真实 CSV 字节，不重新解析再四舍五入。服务端已有公式注入防护。

## 批量、任务与错误恢复

- 先 `POST /review-sets {run_id}` 生成独立推荐快照，再 GET 项目或 groups。`review-1.0.0` 推荐不能冒充初始保守配对；闭单只读且隐藏于可处理项目。
- `/case-batches/preview` 支持跨页 `all`、`ids/exclude_ids`、逐项 `choices`、分组、派单及共同结论。预览不占余量。
- `/case-batches/{id}/commit {}` 重新检查权限、版本及余量。共享余量和整单为原子处理组；部分组跳过/失败仍可能返回 200，必须检查 `succeeded/skipped/failed/ready/reasons`。
- `/case-batches/{id}?page=1&status=skipped` 按状态分页，每页固定50。重新生成快照后 `{set_id,retry_batch_id}` 仅重试未成功项目，不能盲目重复提交成功组。
- `/jobs {scope}` 创建后台任务，随后轮询 `/jobs/{id}`；建议1.2秒间隔。`queued/running/succeeded/failed/interrupted` 与 stage/progress 分开展示，只有成功发布的 run_id 可用于查询。
- 一般错误含 `code/message`；部分历史批量参数错误只有 message。401 重新登录，403 检查权限/入口/CSRF，404 重新查询，409 刷新当前状态并人工复核，422 修改输入，429 按提示等待，500 留存去敏诊断。
- 网络中断/超时不代表写入回滚。先查询单条、任务、批量或审计结果，不自动重发写请求。快速更换筛选时取消旧读取并以请求代次屏蔽迟到响应。

## 更新与校验

在 backend 目录执行 `go run ./cmd/apispec ../docs/api` 重新生成两种规范。DTO schema 从 Go 生产类型反射，动态响应及输入语义由显式契约描述。修改路由或字段必须同步契约、客户端及测试。`api_contract_test.go` 检查真实 Gin 路由、规范快照和实际 HTTP 响应；完整规范另以 OpenAPI 3.1 验证器检查。当前无交互式 Swagger 页面。
