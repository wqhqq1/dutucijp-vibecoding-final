# FR-14认证方案依据

核查日期：2026-10-14。这是实施方案和官方资料核查，不是安全认证或已通过的应用测试。

## 已获本人要求与实施默认

本人要求所有账户首次强密码（可自动生成），然后必须配置Passkey或2FA。具体实现默认采用16至128字符密码、128位随机生成、Passkey用户验证、认证器TOTP、受限首次会话和恢复码；这些参数由Codex细化，区别于本人原话。

密码重长度、常见弱密码拦截及限流，允许长口令与粘贴。16字符下限为本项目选择；NIST区分单密码与多因素口令长度，不把本项目参数说成其强制原文。[NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html#passwordver)是参考；本课程本地回环应用不宣称取得NIST等级认证。

密码使用加盐Argon2id，初始64MiB/3次/并行1；调参不低于列出的19MiB/2次/并行1组合。依据为[OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。与数据散列SHA-256区分，密码不得使用普通快速散列。

Passkey按[W3C WebAuthn](https://www.w3.org/TR/webauthn-3/)验证账户、公钥签名、一次性挑战、RP ID/Origin及用户验证，要求UV。同步凭据计数可能为0，不能简单强制递增。RP ID为localhost，固定浏览器入口http://localhost:8080；回环来源的可信上下文依据[W3C Secure Contexts](https://www.w3.org/TR/secure-contexts/#is-origin-trustworthy)，浏览器与实际设备的支持待真机验证。更换来源不会静默复用旧绑定。

TOTP参考[RFC 6238](https://www.rfc-editor.org/rfc/rfc6238.html)，采用认证器应用，不需短信邮件。服务端原子记录消费步，成功验证码不可重放；二维码取得本身不证明配置成功。具体窗口、限流、加密和恢复流程为项目设计，详见怎么做.md。

## 实施依赖与验证边界

Go认证库候选选用官方维护仓库[go-webauthn/webauthn](https://github.com/go-webauthn/webauthn)、[pquerna/otp](https://github.com/pquerna/otp)与golang.org/x/crypto/argon2。版本在实施时核验Go兼容性并锁入go.mod/go.sum；本次未安装或运行这些库，不借用其介绍冒充项目已验收。

TC-33至TC-48覆盖门禁、密码、绑定、来源挑战、跨账户、重放并发、受限恢复、限流、会话与秘密保存。协议层可用隔离测试凭据及虚拟认证器；本人还须用真实设备/认证器分别验证两种方式并存证。原始密码、二维码、初始化令牌、会话密钥和恢复码不上传公开仓库。
