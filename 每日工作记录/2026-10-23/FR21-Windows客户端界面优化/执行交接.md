# FR-21 Windows 客户端界面优化交接

2026-10-23，Asia/Shanghai，Claude Code。本人要求“优化 ChatGPT 设计的初版 Windows 客户端”。基线为 7515e19（FR-21 WinUI 3 客户端）。本轮只改 `desktop/` 的界面层与隔离界面宿主，并新增本记录；后端、API、ViewModel/网络层、认证规则、数据库、`dist/windows-x64`、teacher-demo 及中期材料均未修改。未启动正式后端，未使用真实账户、Passkey、TOTP 或恢复码。截图全部来自隔离合成数据宿主或无后端的发布构建，不是官方业务数据或本人操作证据。

## 设计方向

把网页端“对账簿”视觉语言移植为原生 Fluent：墨色文字、唯一青绿强调色（#0D6870，覆盖系统强调色）、三种固定的差异状态色（待处理琥珀、处理中蓝、已关闭绿），以及朱红印章，用作标题栏品牌标记和已结案印章。编号、时间、精确价格等数值统一用等宽字体，数字列右对齐；总数按账簿惯例加双横线。

## 行为与协议

接口路径、请求体、分页、排序、导出、版本号、请求号、写锁、代次屏蔽和请求取消均未改变；`AppViewModel`、`BackendClient`、`ClientSettings`、`Models` 未修改。只在以下几处做了与界面直接相关的调整：

- 批量预览只提交与操作有关的字段：非派单时 `assignee` 发空字符串，非关闭/结案时 `conclusion` 发空字符串。后端本就只在 assign 时解析 assignee（`backend/internal/web/review.go`），只在 close/approve 时校验 conclusion（`backend/internal/store/batch.go`）。这样避免隐藏输入框中的旧内容被提交。
- 单条派单不再默认选中名单第一人，须选择或输入账户。
- 编辑或申请时国家范围为“全部国家”，`countries` 提交为空数组，符合 FR-19 接口约定。

## HiDPI 模糊排查

本人反映页面在高 DPI 下非常模糊。实测（本机 192 DPI，即 200% 缩放）：

- `dist/windows-x64/Reconciliation.Windows.exe` 已嵌入 PerMonitorV2 清单，运行时窗口 DPI 感知为 PerMonitorV2、DPI 192，物理像素截图清晰（截图/HiDPI-发布版-清晰-物理像素.png）。
- 本轮反复启动的隔离宿主 `Reconciliation.UI.Tests.exe` 没有应用清单，被系统按 DPI 不感知处理并位图拉伸，物理截图模糊（截图/HiDPI-测试宿主无清单-模糊-物理像素.png）。本人两次看到的模糊窗口与宿主启动时间一致。
- 已让宿主链接客户端的 `app.manifest`，并删除过期的合并清单后重建。复验嵌入清单含 dpiAwareness。截图运行改为窗口移出屏幕、进程内渲染，不再在桌面弹出窗口。
- 另修正了 TOTP 二维码的高 DPI 清晰度（见上表）。
