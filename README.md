## 已确定的边界

后端 Go + Gin + SQLite，前端 React + TypeScript + Vite。Python 仅用于原始 Excel 数据准备。
首版使用工作表 Year 2009-2010 的 525,461 条原始记录；最终必须支持两个工作表合计 1,067,371 条原始记录。
采用唯一候选且余量足够的保守配对，支持部分退货，多候选由人核查。
财务查看全部并派单，处理人核查自己的差异，管理员管理全部。
每个账户首次先配置强密码（可自动生成），再验证绑定Passkey或TOTP，完成后才开放业务；后续使用Passkey或密码加认证器验证码登录。

## 当前可运行命令

在项目根目录的PowerShell执行，首次需联网安装依赖及获取官方数据：

```powershell
./tools/bootstrap.ps1
./tools/verify-environment.ps1
./test.ps1
./verify-data.ps1 -Scope benchmark
./verify-data.ps1 -Scope year1
./reproduce.ps1 -Scope year1
```

`reproduce.ps1`在项目外创建独立验证库，完成数据准备、Go导入、配对、证据输出及幂等重跑；不会覆盖已有业务处理历史。也可传入benchmark或all，后者未完成官方实跑验收。完整命令、证据读取与恢复范围见[运行说明](运行说明.md)。

## GitHub 备份与恢复

每天完成真实提交和归档后，通过 GitHub 插件保存最新项目文件、当日派生记录和原始 Git bundle。
云端 API 生成的快照提交与本地开发提交不是同一套 SHA；备份清单记录本地 HEAD、文件散列及 bundle 散列，不将云端快照时间冒充开发时间。
要还原本地完整开发历史，先从 GitHub 获取 `_备份/项目存档.bundle`，然后运行：

```powershell
git clone 项目存档.bundle restored-project
```

bundle 不包含原始数据；按记录的 UCI 地址和 SHA-256 获取数据后复现。截图、报告和 PPT 随真实工作逐步加入。
