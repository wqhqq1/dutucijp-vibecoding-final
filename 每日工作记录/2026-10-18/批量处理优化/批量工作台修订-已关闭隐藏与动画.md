## 1. 改了什么

### 1.1 已关闭项目不再进入批量工作台（后端口径修改，要求 3、4）

原来勾选表里能看到已关闭行（复选框禁用），选择"当前筛选全部"时它们也会被带进预览，再整组列为"已跳过"。这就是混乱的来源。

- `store.reviewMatches` 在筛选条件之外排除 `status=closed`。列表、分组、全选和预览共用这一个函数，所以四处口径一致。只做筛选比对的旧逻辑改名为 `reviewFilterMatches`。
- `ListReview` 新增 `readonly`，即"命中筛选但已关闭"的条数。快照 `counts` 新增 `closed`。界面只提示"另有 N 条已关闭，只读，可在差异列表查看"。
- `PreviewBatch`：选中的已关闭项计入 `readonly`，不再进入批次。所选全部已关闭时返回 `closed` 错误。
- 预检改为先判断 `closed` 再判断版本。旧快照里的项目如果之后被关闭，原因会写"已关闭项目只读"，不再是含糊的"版本已变化"。
- "未明确方案"细分为三种原因：已配对（请改用批量结案）、没有合格推荐、未选择（最近并列）。
- 结果：勾选表里不再出现禁用的复选框。复选框只在请求进行中暂时不可点。

### 1.2 预览与结果按类分开（要求 3 和其他改进）

- `GET /api/case-batches/:id?status=ready|succeeded|skipped|failed` 每次只分页一类结果，其他值返回 422。
- 不带 `status` 时，预览默认显示"可提交"，结果默认显示"成功"。
- 响应新增以下字段：
  - `reasons`：跳过和失败按原因汇总计数。
  - `groups`：处理组数。
  - `view` / `view_total`：当前显示的类别及其条数。
  - `readonly`。
- 弹窗顶部的计数卡同时就是切换标签。"将跳过/失败"页先列原因汇总，表格列改为"原因"。"关联处理组"一列显示"与另外 N 条同组处理 / 单独处理"，不再显示难懂的组号。

### 1.3 分组翻页对齐（要求 1）

- 分组区改为三列网格，按底边对齐：分组依据、当前组、组翻页。
- 组翻页显示"共 N 组 · 第 p/P 页"，翻页按钮只有一页时隐藏。
- 手机宽度下改为单列。

### 1.4 动画（要求 2）

- 整个工作台统一用同一条缓动曲线，打开较慢（0.24 秒），关闭较快（0.16 秒）。
- **弹窗关闭**：原来直接卸载，没有任何过渡。现在先加 `is-closing`，弹窗和遮罩一起淡出，再卸载。
  - Chrome 对模态 `<dialog>` 按 Escape 会原生直接关闭，跳过退出动画，所以 Escape 改在 keydown 中处理。
  - 卸载后把焦点还给打开弹窗的按钮。
- **步骤切换**：当前步骤的左侧标记改为内阴影。原来改的是边框宽度，会让内容横移约 3px。
- **翻页、筛选加载**：原来先清空表格，表格塌缩后再撑开。现在旧行保留、变淡并设为 `inert`，旁边显示"正在整理…"，表格高度不变。原来顶部固定的"处理中"胶囊在弹窗打开时不再出现。
- **展开说明、预览提示条、分组区出现**：都加了轻微淡入。
- 已有的 `prefers-reduced-motion` 全局规则继续生效。

### 1.5 其他改进

- 表头复选框可选本页，部分选中时显示半选状态。原"选择本页"按钮删除；已选行有浅色底。
- "预览所选"不可点时，按钮旁说明原因（先勾选 / 先填写结论）。
- 每个批量操作下方有一句说明：做什么，适用于哪些项目。
- 视图切换改为分段按钮（`aria-pressed`）。步骤标题改为"确定处理范围 / 勾选项目并确认方案 / 选择操作并预览"。
- 弹窗内原来正文和表格各有一条纵向滚动条，现在只保留正文一条。
- 模拟预览接口 `frontend/dev/mock-api.ts` 同步了新契约。它仅用于开发，不进入 dist。
